## 1. 产品边界与职责

**【已确认规则】**这是独立的新模组，单独运行时即可改造普通生存，也能与 YumisSkyIsland 共同安装。不依赖空岛领地服务启动，不把战斗等级当岛屿等级，不把鬼剑士当原有七种副职业之一。本轮仅生成本目录三份文档，不创建新工程、不修改空岛源码或配置。

**【已确认规则】**首版角色1～50级，初职鬼剑士，20级起可通过任务转职剑魂；武器只做自制太刀。首版关闭PVP。新的防御公式替代原版护甲与护甲韧性的战斗减伤，不能在新公式之后再减一次原版护甲。

**【建议测试值】**未来工程使用 Minecraft 26.2、Java 25、Fabric；以当前仓库核实的 Loader 0.19.3、Fabric API 0.156.0+26.2、Loom 1.17.21作为起点。拟用模组ID `yumis_dunguen_and_fight`。玩家端和服务器均需安装协议兼容的新模组；服务端保留实体AI、寻路、区块和世界生命周期。客户端渲染及技能模拟代码不得被专用服加载。

### 1.1 核心原则

**【已确认规则】命中、技能、位移、MP、冷却、造成和承受伤害全部由玩家本地运行；服务器只接收战斗结果中的百分比，不重算伤害，不设计伤害反作弊。**

**【建议测试值】**将“战斗模拟”与“共享事实”分开：服务器保存角色进度、装备和背包、队伍、副本、共享血量、死亡及奖励，负责操作去重和持久化。学习技能的等级/SP检查、扣物发物、PVP禁用和空岛权限仍属于游戏状态规则，不增加距离、攻速、命中、倍率、MP消耗或冷却是否合法的服务端复核。

## 2. 属性与伤害

### 2.1 属性清单

**【已确认规则】**个人属性包括生命、魔力、力量、智力、精神、物理攻击、魔法攻击、物理防御、魔法防御，光/火/冰/暗各自的强化与抗性，以及掉宝率。元素是四个独立数值，不是一个总强化。战斗等级经验与原版经验彼此独立。

**【建议测试值】**U面板同时展示“基础攻击”和代入主属性后的“面板攻击”，避免玩家把主属性乘两遍。精神每点增加2最大MP、2魔防和0.04 MP/秒恢复；不增加生命或主攻击。基础元素强化、抗性、掉宝率均为0。暴击、命中、闪避和额外职业不加入首版属性模型。

### 2.2 固定成长与自由点

**【已确认规则】**令等级为 `L`，`n=L−1`。基础生命 `HP=100+20n`。每次升级获得2点自由属性，1级没有额外自由点；50级共98点。仅分配力量、智力、精神，脱战免费重置，不清除装备和已学技能。

**【建议测试值】**下列是普通装备的理想参照模型，不包括技能、品质、词条、附魔、饰品或血月加成。随机普通装备可具有1～50的物品等级；1/5/10/15/20/25/30/35/40/45/50是造型和制作档位，不代表中间等级不能掉装备。

| 项目 | 模型 |
|---|---|
| 自动力量 | `20+3n` |
| 自动智力 | `15+2n` |
| 自动精神 | `10+2n` |
| 角色基础物攻、基础魔攻 | 各 `5+n` |

### 2.3 伤害计算顺序

**【已确认规则】**每次攻击明确为物理或魔法，并带0～4种元素。物理用力量、物防；魔法用智力、魔防：

```text
面板攻击 A = 基础攻击 B × (1 + 主属性 / 100)
防御减伤率 = def × 0.001 / (def × 0.001 + 1) = def / (1000 + def)
通过防御的比例 = 1000 / (1000 + def)

有元素：差值 d = max(攻击携带元素e的强化[e] − 目标抗性[e])
无元素：差值 d = 0 − max(目标四种抗性)
元素倍率 E = max(0, 1 + d / 120)

最终伤害 D = A × 技能倍率 × 1000/(1000+有效防御) × E × 其他已定义伤害乘区
本次扣血比例 f = D / 攻击者视角的目标满血
```

**【建议测试值】**物防、魔防最低取0；暂不引入负防增伤。多元素差值相同时使用光/火/冰/暗固定顺序，仅决定表现标识，不重复伤害。物理/魔法不等于无属性/有属性：物理也可带暗，魔法也可无属性。破甲先修改本次有效防御，不能永久改其他人的目标属性。

**【已确认规则】**12点差值对应10%线性变化。`d=−120`及以下直接免疫；本地显示“免疫”，不提交伤害、不产生伤害击退。动作、剑气、已消耗MP与冷却仍正常发生，免疫不是取消施法。

**【建议测试值】**百分比以“满血的份额”表示，`0.10`是扣满血的10%，不是扣当前剩余血量的10%。内部不逐段取整，显示伤害才取整或显示一位小数。物理/魔法/元素只在本地算一遍，服务器应用百分比不能再触发原版护甲、韧性、附魔防御或第二次易伤。

**【建议测试值】**技能表100%在公式中取1、320%取3.2；掉血份额0.1在UI显示10%。不要将这三种百分数表示混用。

| 物防500 | 减伤1/3，200伤害通过后133.333… | 已确认规则的推导 |

## 4. 等级、经验、SP与恢复

### 4.1 经验曲线

**【已确认规则】**通过击杀获得个人战斗经验，目标1～50级约20～30小时有效游玩。同步后的低级区域也提供更高经验与更高级装备。无额外独立“世界成长等级”。

**【建议测试值】**使用以下首轮曲线，L级升级需求只对1～49级有效：

```text
同有效等级普通怪基础经验 X(L) = 10+2L
L→L+1经验需求 = (10+2L) × (20+5L)
同级普通怪等价击杀数 = 20+5L
1→50等价总击杀数 = Σ(L=1..49)(20+5L) = 7,105
```

| 1 | 300 | 12 | 25 |

| 10 | 2,100 | 30 | 70 |
| 20 | 6,000 | 50 | 120 |
| 30 | 11,900 | 70 | 170 |

**【建议测试值】**每分钟4～6只合格同级普通怪，对应约29.60～19.74小时；这是包含寻怪与移动的基准，不把连续出刀时间直接当升级时间。精英经验×3；难度经验暂定普通/冒险/勇士/王者/地狱为1/1.2/1.45/1.8/2.2。高难怪更耐打，不保证纯经验效率必高于普通。组队、范围技、刷怪设施会改变效率，必须实测；首版不加入反作弊或额外防刷系统。

**【建议测试值】**服务器以结算时已冻结的个人有效挑战等级计算经验；关闭同步的高级玩家击杀低级怪仍按原怪等级奖励。50级不再升级或继续发SP/自由点；经验面板显示满级，未来提高上限的经验保留规则待设计。

### 4.3 恢复、死亡、环境

**【已确认规则】**脱战10秒后每秒恢复2%最大生命；战斗中不新增自动回血。MP持续恢复、脱战三倍。死亡保留物品、原版经验、战斗经验、等级、SP、货币、装备、任务与全部个人进度，没有扣罚。副本内满血满蓝回入口，可反复返回正在进行的战斗，不使用观战等待或全灭失败规则。

**【建议测试值】**施放攻击技能、有效攻击、受到敌对攻击或伤害时刷新本地10秒战斗计时，免疫的敌对命中也刷新；脱战切换同步、洗点、修改自由点。普通死亡在既有合法复活点满血满蓝复活。装备无额外死亡耐久损失；正常使用耐久另按装备定义。死亡不用于刷新技能冷却，保留客户端最近同步的剩余时间。

### 6.1 原等级与有效等级

**【已确认规则】**出生时保存怪物原等级，主世界1～10、下界25～35、末地45～50。卸载重载不重抽。个人开同步时 `有效等级=max(原等级, 本人等级)`；关闭时使用原等级。低级玩家不能把高等级怪下调。没有额外可升级的世界等级系统。

### 6.2 百分比共享

**【已确认规则】**同一实体只有一份共享剩余比例 `q∈[0,1]`。玩家i的显示生命为 `q×H_i`，其中 `H_i` 按其有效等级及本次难度等乘区计算。服务器应用 `q'=max(0,q−f)`，其他观察者按自己的H换算损失值。

| 项目 | 50级同步玩家 | 10级玩家 | 状态 |
|---|---:|---:|---|

| 50级玩家造成1,000伤害 | 扣满血10% | 显示受到80伤害 | 已确认规则的推导 |
| 共享剩余90% | 显示9,000 | 显示720 | 已确认规则的推导 |

**【建议测试值】**怪物攻击不同玩家时，由各受害客户端按自己的有效等级、怪物攻击、本人防御和元素计算；范围攻击可对不同人产生不同数值。客户端选择的攻击元素不会让其他观察者再按其抗性重算一次扣血。个人等级、同步状态、难度与组队倍率采用一次遭遇快照；升级获得进度立即落盘，但战斗投影待脱战后更新，避免同一段交战中途改奖励档位。

**【建议测试值】**同一怪物在某人关闭同步、另一人开启同步时也共用q。奖励按各自遭遇快照结算。普通区域被同步到50级后可掉50级通用装备，不能据此生成尚未定义的神话或副本独占装备。可反复刷安全低级区域是该机制的已知结果，首版不悄悄加额外降奖励规则。

**【已确认规则】**首版暂停怪物互打和无主怪物环境伤害，不安排客户端代算，也不引入服务器伤害公式兜底。玩家本人摔落、岩浆、火焰等不属于暂停范围。

**【已确认规则】**人数只增加副本怪物生命，不加攻击；公共大世界不因附近人数扩血。8人地狱生命倍率123.6，按8份等量输出的人均压力15.45倍普通单人；精英再乘3。不要另加一遍线性人数倍率。

### 8.3 进入、退出、复活与重连

**【已确认规则】**副本提供同步属性/解除限制两种模式，队长整队选择模式和难度。同步模式仍按每个人的有效等级投影，解除限制按怪物原等级；不是把全队强制改成同一等级。死亡入口立即满血满蓝复活，可反复返回，已得经验装备保留。

**【建议测试值】**流程为选副本→选择模式/难度→在队成员确认→冻结入场名单和人数→创建实例→记录各自外部返回位置→统一进入。1～8人，单人也可进入。具体地图最低等级由未来地图定义，不用解除限制绕过穿戴等级要求。

**【建议测试值】**实例运行中不能增加新成员，允许冻结名单内成员重连；离开、踢人、掉线不下调人数血量，避免动态改血。主动离队可退出实例，已领取奖励不收回，本轮不再加入。返回外部位置失效时使用对应世界合法复活点，不回已删除岛屿。

**【建议测试值】**掉线重连回实例安全入口，不靠重连刷新MP、冷却或怪物q；死亡复活才回满。全员离开后实例保留10分钟、整体暂停，不补离线模拟，超时关闭。服务器重启结束未完成实例、保留已落盘进度和奖励，登录回安全返回点；首版不恢复半场副本。没有进入费或消耗券，未来加入费用时需另行确认。

**【建议测试值】**怪物死亡即时结算奖励，通关后只发独立配置的通关奖励，不再重复杀怪收益；地图未设计时不虚构通关奖品。重新开本创建新实例ID和生命周期，旧百分比请求不能打到新怪。没有全灭自动失败或死亡次数上限。

**【待设计】**具体副本地图、波次、Boss、剧情、独占装备和通关奖励。

## 10. 全客户端模拟与百分比协议

### 10.1 状态与数据流

**【已确认规则】**服务器不接收并复算“原始攻击/力量/防御/技能倍率”作为伤害结算前提。客户端根据已取得的角色、装备、怪物模板、遭遇和兼容快照运算，提交最终满血份额。不能把本地运算偷偷改成等待服务器确认命中后才计算。

**【建议测试值】**协议最小职责如下；这些是拟定数据契约，不是已存在的Java类：

| 契约 | 方向 | 主要内容 |
|---|---|---|
| CombatContext | 服务端→本人 | 协议/规则版本、会话ID、本人进度、维度/实例、怪物UUID/生命代次/原等级、遭遇难度/人数、兼容效果版本 |
| PercentReport | 客户端→服务器 | 会话、维度/实例、目标UUID/生命代次、操作号、DAMAGE或HEAL、deltaFraction；可附紧凑技能/来源事件标识 |
| PercentAck / HealthDelta | 服务端→相关玩家 | 已处理操作号、目标状态修订、权威q、实际应用份额、是否死亡 |
| ClientSkillState | 本人→服务器 | 本地MP、剩余冷却、施法/位移状态的合并快照，不作合法性审核 |
| CastVisual | 客户端→服务器→附近玩家 | 施法ID、技能、起点/朝向、阶段和时间，用于各机生成特效，不逐帧上传粒子 |
| KillSettlement | 服务端内部/→本人 | 唯一死亡ID、实际贡献、个人有效等级、奖励和存储回执 |

**【建议测试值】**技能位移由本机碰撞与动作模拟，复用必要的玩家移动同步，不再让服务器模拟一次技能轨迹；未来需验证原版移动纠正不会拉回合法技能。服务器可以保留管理和世界权限，不能新增距离/速度型战斗反作弊。远程玩家看到的只是表现事件与位置结果，不代替他计算第二次伤害。

**【建议测试值】**受管怪物的q是权威数据，原生实体生命只作固定代表最大生命下的投影，不随每个观察者切换MAX_HEALTH。玩家原生最大生命/生命可映射本人RPG状态。进入百分比管线的原版hurt/治疗/回血入口须抑制原有扣血并改发上下文事件；应用结果时打桥接标记，不能再触发一次hurt或吸血。生效范围外的实体不能被全局清空生命处理。

### 10.2 去重、并发与死亡

**【建议测试值】**服务器仅做格式、有限数值、有效目标生命周期、会话、操作去重和既有世界权限处理；不检查伤害大小是否合理。deltaFraction必须有限且非负，伤害允许大于1表示过量。DAMAGE和HEAL分开，不用负数偷换操作。数值异常保护是防止NaN污染存档，不是伤害上限或反作弊。

**【建议测试值】**每个会话操作号唯一；同操作重传返回原回执，不再次应用。目标用UUID＋维度/实例＋生命代次，不能只用重用的数字实体ID。过期生命周期拒绝应用，重登使用新会话并先恢复旧会话已提交结果，不把旧队列重新编号当新伤害。

**【建议测试值】**对同目标按服务器接收顺序串行处理：`实际扣除=min(q,f)`；剩余3%收到8%只记3%实际贡献、q归零一次。后到伤害回执为死亡/0贡献，不第二次发奖。HEAL在死亡后不复活实体；玩家复活生成新生命代次。独立客户端的目标状态修订落后不应导致合法并发伤害被丢弃；身份代次与血量修订不是同一个字段。

**【建议测试值】**唯一死亡ID绑定持久化奖励回执，再触发实际实体死亡与必要旧模组事件；重启读取已处理结果，不能再随机一次装备。记录共享q与结算边界，安排崩溃故障注入。保存失败时显示奖励待处理，不先显示已到账再丢结果。本地预测血条只覆盖未确认份额，收到确认剔除对应预测，避免把自己命中扣两遍。

**【建议测试值】**进度、装备和学习由服务器保存；技能运行状态信任本机。MP/剩余冷却在施法阶段变化、死亡、换维度和断线时合并保存；本地计时采用单调时钟，重建玩家对象不归零。服务器保存相对剩余时长及记录时刻用于恢复，不能比较服务端时间戳与客户端单调时钟。突然断线仅能恢复最后收到的状态，这是本架构接受的边界，不添加反作弊复核。

### 10.3 通信与性能

**【已确认规则】**本地计算旨在减少服务器战斗模拟负担并降低不必要通信；百分比与绝对伤害都只是数值，单纯换单位不保证节省带宽。

**【建议测试值】**首次接触按版本下发模板/兼容快照并缓存，不为每刀发全量属性。伤害结果最长50ms合并一次，同批保留目标、来源类型和完整操作身份；致死、受害和控制表现优先立即发送。回血200ms合并，HUD最多10Hz同步并本地插值，施法/MP/冷却以阶段变化为主。精确频率需实测，不是性能承诺。

**【建议测试值】**只向正在追踪实体、附近观察者或明确订阅目标血条的玩家发送增量；不全服广播每个目标HP，不逐tick同步未变MP，不重复上传粒子。入场一次快照，后续修订增量；失去追踪取消订阅。多段和范围攻击按有界批次编码，超限分包/排队而非静默丢命中；详细容量根据26.2网络实测定值。

**【建议测试值】**记录5/20/50在线玩家与8人范围技场景中的包数/字节、P50/P95确认延迟、服务器tick、客户端帧时间、队列与分配量。客户端确实会多承担技能碰撞与公式；仍有服务器AI、区块、结算、广播开销，不能声称“客户端计算后服务端几乎零成本”。
