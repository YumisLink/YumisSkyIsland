# Yumi’s Sky Island 经济系统设计修订

日期：2026-10-13。目标版本：Minecraft 26.2、Fabric Loader 0.19.3、Fabric API 0.156.0、Java 25。

本文件为先于源码制定的经济设计与逐项价目依据。现已实现对应开发源码；实际 26.2 注册表解码和客户端验证见[实现与验证记录](IMPLEMENTATION_STATUS.md)。配置保留草案标记，价格与完整生产链平衡仍需继续审阅。

Q34～Q48改版以[确认稿](SHOP_REVISION_REVIEW.md)为准：旧基础价×10、普通收购÷100；所有首种及允许购买的怪物材料购买另×100，收购不含这部分加价。原木可买可卖、其他木材方块仅收购；大量成品整类禁交易。三项推进方块与19种模板保留特殊供货。

## 已确认的新增规则

| 项目 | 最终规则 |
|---|---|
| 悬停 | 在原版物品提示中追加该物品实际价值和新增放置的岛屿经验；缺配置时省略对应行 |
| 损耗 | 剩余100%→80%，价值100%→50%；80%→50%，价值50%→0%；50%及以下价值0 |
| 附魔 | 按附魔ID、实际等级查表，各系数相乘，由配置调整 |
| 岛等级 | 0～100级；把旧最高30级的建设量门槛细分，保留未截断的原始分数 |
| 财富 | 64位非负整数金币，支持数亿及更高余额，显示万/亿 |
| 普通商店 | 只购买普通稀有度的商品 |
| 稀有度 | 按物品种类分普通、稀有、史诗、传说，与制造品质独立 |
| 每日商店 | 每队独立抽取，只从刷新时已解锁的稀有/史诗/传说候选中随机上架 |
| 隐藏商店 | 每个游戏自然日每队5%概率；当日替代每日商店，提高高稀有度货物概率 |
| 制造品质 | 继续保留普通/精良/稀有/史诗/传说；所有商店产出普通制造品质 |
| 库存 | 特殊商店每日限量，所有队员共享；逐物品配置数量 |
| 保底 | 完全随机，不提供保底，不保证某个物品在有限天数内出现 |
| 轮次 | 24000有效服务器游戏tick；睡眠、时间命令、重开、重登、升降级不能重抽 |
| 原版交易 | 职业村民/流浪商人禁交易；猪灵以物易物保留，村民繁殖/工作/铁傀儡生成保留 |
| 生电等级 | 只限制商店购买核心材料；自行合成、原版获取、放置与生产不封锁 |
| 日售出阶梯 | 全队按同类原料等份计数：前1000正常收购，1001～10000乘0.5，超过10000乘0.1，无数量上限 |
| 出货箱 | 普通箱子外观、特殊合成，红石无→有时出售一次，收益入所在岛队伍钱包 |

“隐藏商店大幅提高”的对象是物品稀有度，不出售职业高品质装备。附魔书属于带固定附魔组件的普通物品变体，不等同于高制造品质。

## 悬停提示与统一估值

建议呈现：

    物品价值：7500金币/件
    正常收购：75金币/件
    下一件预计收购：37金币（今日原料额度已进入半价段）
    岛屿经验：预计 +25（第65个同类方块）

需要折价或倍率时补充一行原因，例如：

    稀有制造品质 ×2；附魔合计 ×2.925；耐久90% → 价值75%

物品价值和收购价值显示这件真实物品的品质、附魔、耐久结果；不是只显示一个同名新物品的基础价。下一件报价还包含共享日额度，压缩物跨阶梯时按其份额拆分；批量报价另按真实数量预览，不能简单乘单件已经舍去的小数。已配置但因耐久折为0的装备显示0与原因；没有价格定义的物品不显示价值/收购行。没有计分映射、计分为0、当前维度不计分或尚未同步队伍计数时不显示放置经验行。

计分提示是“新增放置预估”，不承诺替换方块、墙面变体、床/门双格放置等真实操作的净差。游戏实现须依据 Item.BY_BLOCK 和实际使用处理器建立映射；支持已知多格物品时累加所有新增格的边际值。服务端成功放置时才结算真实变化。

使用 Fabric ItemTooltipCallback 在物品基本提示后追加内容，因此普通背包、工作台、商店及其他使用原版提示的界面均可显示。TooltipContext 没有当前玩家/目标位置，不在每次悬停时发网络请求。

服务端同步报价、附魔/耐久规则、当前队伍、每日原料额度和计分直方图快照；正常建造与销售合并发送计数增量。客户端本地计算存量边际计分及下一件预计收购价。乱序、旧市场轮次或旧岛世代的数据丢弃，计数版本缺口才请求完整同步。切换队伍、重开和刷新完成时更换快照，销售最终以服务端版本复核。

### 金额公式

1. 今日基础价 P = max(100, floor(基础价格 × 今日行情系数))；新基础价格为旧版10倍。
2. 制造品质 Q 为其配置倍率，所有商店的 Q=1。
3. 附魔倍率 E = 每个合法附魔等级系数的连乘。
4. 耐久倍率 D 为下述连续函数；不损耗物品 D=1。
5. 物品价值显示 floor(P×Q×E×D)。
6. 购买为 floor(P×Q×E×购入倍率)；正常收购未取整金额 P×Q×E×D÷100。购入倍率普通为1、首种及允许供货的怪物材料为100，购买加价不进入收购价值。
7. 对该原料组今日已售量，按前1000份×1、接下9000份×0.5、其后×0.1分段。每件按配置的原料份额计算，跨界拆分权重。
8. 本笔所有可售行先精确求和，最终收购金额 floor(各行含阶梯的金额之和)。

内部使用定点数/有理数和检查过的整数运算，最终金币只舍去一次小数。超出64位余额可表示范围的交易拒绝，不产生负数或环绕余额。改耐久上限的品质装备按实际最大耐久计算比例。

令 r=剩余耐久/实际最大耐久：

- 0.8≤r≤1：D=2.5r−1.5。
- 0.5≤r<0.8：D=(r−0.5)/0.6。
- r<0.5：D=0。

| 剩余耐久 | 价值倍率 |
|---:|---:|
| 100% | 100% |
| 95% | 87.5% |
| 90% | 75% |
| 80% | 50% |
| 70% | 33.333…% |
| 65% | 25% |
| 60% | 16.666…% |
| 50%及以下 | 0% |

例如某个仍有价格定义的物品基础价值100000、制造品质×2、三个附魔×1.5/1.3/1.5、剩余90%耐久、未超过今日原料额度：单件收购为 floor(100000×2×1.5×1.3×1.5×0.75÷100)=4387金币。处于半价或十分之一段时继续乘其阶梯权重，再对整笔交易最终取整。工具和战斗装备本轮已取消经济定义，不因此恢复收购。

附魔读取 EnchantmentHelper.getEnchantmentsForCrafting：装备读取 ENCHANTMENTS，附魔书读取 STORED_ENCHANTMENTS。43种原版附魔、最高等级、互斥关系、宝藏/诅咒标签来自26.2资源；倍率由本项目配置。合法额外附魔不再一概拒收。未配置附魔、超原版最高等级或非法互斥组合不自动收购。

估值范围与购买上架范围分开。稀有物品即使今天没上架仍可按定义出售；出售不要求达到其购买解锁等级。非空容器、有内容的束口袋/潜影盒、未知特殊组件继续拒绝自动出售；不按普通同ID物品处理贵重内容。命名物品继续需要单件明确确认，批量售卖跳过。

售出总额舍去后为0时不扣物、不增加计数。日售出额度沿用稳定partyId与市场轮次，重开和队员变化不清空；手动、商店和出货箱共用。历史铁粒1/9、铁块9和装备等原料映射保留，但当前禁交易物品不参与出售。仍可交易的不同物品共用组额度、各自应用行情。完整等份与示例见[售出额度表](../config/yumis_sky_island/shop/SALE_QUOTA_TABLE.md)。

## 每日/隐藏商店

以下数量和权重是可编辑初稿：

| 参数 | 每日 | 隐藏 |
|---|---:|---:|
| 每队概率 | 95% | 5% |
| 最多商品栏位 | 12 | 16 |
| 稀有权重 | 70 | 15 |
| 史诗权重 | 25 | 50 |
| 传说权重 | 5 | 35 |
| 额外价格倍率 | ×1 | ×1 |

库存默认为稀有64、史诗16、传说1；products.json 的 dailyStock 可覆盖。框架默认12，装备/生物蛋通常1，附魔书1～4。常驻普通商店不设购买库存限额。

抽取流程：

1. 市场轮次前进时，以稳定 partyId、marketEpoch 以及服务器持久种子生成该队当日状态；新建队伍初始化当前轮次一次。
2. 固定当前岛等级快照，剔除禁交易、未解锁、普通稀有度和不允许购买的商品。
3. 投一次5%隐藏判定；结果和库存持久保存，不能在每次打开UI时投骰子。
4. 先按稀有度权重抽档位，再按产品 offerWeight 抽商品。每次抽中从候选中移除该商品。
5. 没有合格商品的档位剔除，剩余权重重新归一化。候选不够时少显示栏位，不以未解锁商品补足。
6. 每次购买检查当前等级、余额、真实剩余库存、报价/轮次版本及背包容量，然后在服务端结算一次。
7. 当天升降级不重抽。购买仍受当前等级约束；新等级商品下一轮才可能出现。库存次日重置，不累计未购买的库存。

模式提示、剩余刷新进度与全队剩余库存放在商店页头。隐藏当日作为每日页的特殊状态显示，不增加NPC或另一套入口。常驻商店继续存在。

每日商品遵守全服统一的当天±10%报价；各队商品列表不同，商品本身的行情价格一致。修改附魔、基准价等配置时作原子重载，报价版本递增，旧报价请求拒绝后重新展示；编辑物品抽取规则不免费重抽当前轮次的池，下一轮使用新规则。

完全随机、无保底是用户确认的规则。钻石、烈焰棒、首张模板、末地框架等在全空世界缺少自然来源，因此只承诺符合等级后有抽取资格，不承诺80～150小时内一定完成主线。供货权重提高机会，不提供强制出现。

## 等级、刷新与后期财富

默认0～100级阈值每级300计分点，100级=30000点，细分旧方案30级的总建设门槛。计分可以继续超过30000，但显示等级最高100。

前64同类方块全额、65～320按25%、321～2048按5%、其后按1%；每块基础点数和档位独立配置。只计算主世界，拆除扣分，放置事件不积累永久人物经验。

六章岛等级初稿：0、3、10、27、50、100。研究费用设计为0、2000、2万、10万、100万、1000万，目前研究玩法未实现。当前特殊供货目标包含500万的升级模板、1000万的末地框架及高价怪物材料；鞘翅和龙蛋不再属于商店购买目标。

数亿余额由长期生产/职业经营积累，不通过把显示数字乘一个常数实现。钱包采用有符号64位整数的非负范围，运算禁止浮点金额。示例：145235522→1亿4523万5522金币，100000000→1亿金币，2000000000→20亿金币。

### /refresh 的实现预算

- 全服共享每tick 1000微秒计算预算，不按每个队伍各给1毫秒。
- 每tick最多扫描2个区段、发出1个新已有区块请求；最多2个加载请求在途，具体预算可调整。
- 只扫描已生成/已变更区块，不生成整片10000×10000区域。
- 区块异步请求后等待就绪，不在tick里同步等待磁盘读取。
- 每队最多一个刷新任务，重复请求返回原任务状态；全服队伍轮转处理。
- 空区段跳过；使用 palette计数，逐区段切片，不写逐格全领地扫描。
- 扫描期间记录实时增量，完成后发布一致结果；每5秒最多一次进度提示。
- 持久记录任务进度，重启续扫；慢tick时降低预算并将新读取限为每秒一次机会，保留最低进度。全空气区段直接跳过，最多每tick计算两个非空区段；当前可通过 `/is level` 查看进度，尚无独立性能统计命令。

这个预算是实现要求和测量目标，不是已经达到的运行性能承诺。

## 保留的基础玩法规则

- 10～50人服务器，主世界6×6×6泥土、橡树和两桶物资；大厅一层20×20草方块。
- 三维度自然地形与结构为空，正常生物群系/刷怪，门户必要落脚生成保留；跨维度归属受保护。
- 每队10000×10000；不越权放置/破坏/操作容器及跨界机械。
- 个人六职业，队伍共享岛、金币与研究。原个人岛休眠保留，换队不自动合并资产。
- 原版死亡掉落。
- 重开只清本队主世界及队伍金币，恢复初始岛，重新计算等级。地狱、末地、背包、装备、末影箱、职业、任务与研究保留。
- 重开免费无冷却，由岛主二次确认；保留背包意味着可以重复积累开局物资，按确认规则允许。
- 重开不改变 partyId 和市场轮次，不重置当日货物、已购买量及限量库存。
- 重开不清空当日原料售出计数；新主世界领地世代使旧主世界出货箱绑定失效。地狱、末地领地世代保持，保留的出货箱不失效。
- I打开自绘半透明黑色商店，A收藏；正常字号、名称两行，格子默认48且可调40～96，最多30列；左侧仅展示有可购买商品的分类。

本地已完成配置引用、最低价、43种附魔等级表、权重、0～100阈值、耐久边界、原料份额、跨售出阶梯和单次取整检查；实际注册表与组件解码也已验证。商品仍有分类兜底价，全部精确配方套利、50 人性能和持续生产收益尚未完成验收。生电阶段和禁交易/出货要求见[生电计划](AUTOMATION_DESIGN.md)。

实施后验收重点：

1. 任意物品提示按配置有条件追加；交易实际报价与tooltip一致，切换队伍不使用旧计数。
2. 100/95/90/80/70/65/60/50/49%耐久结果正确，50%物品不能卖出金币。
3. 普通附魔与附魔书估值正确，多附魔乘算只最终取整，非法组合不卖。
4. 同队争抢最后一件货物只成功一次；不同队有独立池，允许结果偶然相同。
5. 购买后重登/重启库存不变；重开、睡眠、时间修改、等级反复变化不重抽。
6. 5%模式与分档权重通过大量固定种子模拟检查，低等级隐藏池不越过解锁门槛。
7. /refresh申请立即返回、后台渐进；并发建造不会漏计，50人场景测量最大tick耗时。
8. 数亿与超过32位上限余额保存/同步/购买/出售/格式化正确，溢出交易不改变任何状态。
9. 各入口共享当日原料额度；铁粒不舍为0，铁块和装备不另领份额；0金币整次保留物品。
10. 出货箱仅上升沿卖一次；持续供电、重复通知、带电区块加载不触发新销售；重启恢复不重复入账。
11. 职业村民/流浪商人所有交易入口关闭，繁殖/工作/铁傀儡/猪灵原版行为保留。
