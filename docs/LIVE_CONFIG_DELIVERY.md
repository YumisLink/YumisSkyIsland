# 实时配置、商店改价与方块计分

日期：2026-10-16。适用于 Minecraft 26.2 / Fabric，沿用当前 Java 25 工程基线。本轮面向新测试存档，不新增旧计数和旧刷新任务的迁移流程。

## 使用

1. 管理员输入 `/is admin edit on` 开启本人统一编辑模式，`/is admin edit off` 关闭。任务、商店和实时配置共用此状态；断线或失去管理权限后失效。旧命令中的 `tasks` 已删除。
2. 在游戏内按 **Ctrl＋】** 打开实时配置。左右Ctrl均可，主键可在原版按键设置重绑；其它GUI内不触发，短按有效，长按只打开一次。
3. 点击左侧同级分组，编辑中文表单并点击“保存并生效”。关闭或切换分组会放弃该分组未保存的输入。
4. I控制面板的普通／每日商店中，编辑模式下点击商品进入同页购入基价表单。每日／隐藏页的“查看所有”显示全部已配置商品，包括未解锁、未抽中、售罄、仅收购商品与有效动态蓝图。

“查看所有”不开放额外购买资格。仅收购商品与特殊弹药提供只读说明；实际交易仍由服务端检查等级、轮次、库存、余额和背包。

## 实时白名单

| 分组 | 可编辑内容 | 生效边界 |
| --- | --- | --- |
| 经济与死亡 | 摩拉／金币称呼、死亡首费与递增、复活饥饿值 | 称呼同步在线客户端；费用与饥饿值用于下次事件 |
| 原版交易 | 村民、流浪商人交易开关 | 下次交互与结果提取 |
| 职业经验 | 成功获钓、击杀、四项制造默认经验 | 后续真实行动；已有单品 `baseXp` 优先，地区宝藏箱固定经验不变 |
| 职业商店 | 果实／两种鱼饵价格、果实掉率、每种果实使用上限 | 后续购买、活动和使用；历史经验及已用次数不变 |
| 血月 | 初始概率、未触发增量、敌对刷怪倍率、光照阈值、宝藏池地区蛋概率 | 下次对应判定；不重抽今夜、不热改已加载实体属性 |
| 经验抽奖 | 开关、三个固定档位的扣级成本与四档稀有度权重 | 后续请求；已提交奖品与扣级恢复凭据保持原结果 |
| 刷新预算 | 计算微秒预算、每刻区段数、新读取数、并发读取数 | 下刻调度；已发读取正常完成 |
| 高分方块计分 | 三个累计阈值、四档倍率、队伍通告开关和文案 | 按已有存量重算全部队伍分数与等级，不触发放置通告 |

表单和服务端共用字段白名单。概率采用0～10000万分数；果实上限1～100。实时刷怪倍率0～20，刷新预算1～5000微秒，每刻区段1～64、新读取1～16、并发读取1～32。成本、权重和阈值必须为对应整数范围，阈值严格递增、倍率不逐档增加、每档抽奖权重不可全零。

逐方块基础分、职业经验曲线、血月伤害／速度／生命属性、建造杖与大炮规则、建筑库及注册资源不在本轮实时白名单。

## 方块计分

服务端增减、历史扫描和客户端预估共用 `ScoringSettings` 与 `BlockScorer`。原始存量按注册方块ID独立保存，同ID属性变化不增减数量。

- 空气、水、岩浆、气泡柱固定排除；含水建材正常计分。
- `blocks.<ID>` 条目、其中的 `basePoints` 字段或整个 `blocks` 表缺失均默认1分，不触发默认高分回填。其它显式基础分必须至少1，旧默认0分项已同步为1。
- 基础分1～5恒定计分；>5才按256／2048／8192三个累计阈值递减，默认倍率100%／25%／5%／1%。旧 `tierProfile`、`scoreGroup` 不再控制计分。
- 每档先算单块 `max(1, floor(basePoints × multiplierBps / 10000))`，再乘本档数量；铁块基础15分的四段为15／3／1／1。第256块仍按第一档，第257块才进入下一档。
- 手动放置与建造杖每次从阈值以下达到阈值时通知本队在线正式成员；拆掉再达到会再次通知。大炮、自动变化、刷新、重启与配置重算不发跨档通告。

基础分手改运行实例 `islands/scoring.toml` 后重启载入。启动重新按原始存量计算缓存，不沿用旧规则下的总分。注册ID在所有模组完成注册后验证，未知ID不按1分兜底。

`notices.message` 支持 `{block}`（客户端本地化方块名）、`{threshold}`、`{nextPoints}`、`{nextMultiplier}`，默认文案解释后续实际单块分数和倍率。通告资格由实际放置位置及来源标记决定，不把仅带玩家上下文的自动生长算成手动放置。

## 保存与交易一致性

配置表单保存前检查服务端权限、统一编辑模式、字段白名单、修订号和当前已加载的文件摘要。先验证完整候选文档，再原子替换运行TOML并发布规则；失败不发布候选值。人工注释和未编辑字段保留。其它管理员保存或人工改过文件时，过期请求失败，需重新打开；人工TOML改动需先重启载入。

静态商品只写原条目的 `buyBaseValueCoins`。动态蓝图写 `shop/products.toml` 中的 `buyBaseValueOverrides`，不把运行生成的完整商品行保存到静态目录，避免重启后等级、稀有度和模板元数据失真。原版收购基价、额外倍率、日库存及外置建筑成品费不变。

商品目录分页携带修订号；全部商品和规则到齐后才替换客户端缓存。普通商店购买、职业商店购买及经验抽奖分别携带对应报价／规则版本，过期请求在扣费、扣级或抽奖前拒绝。旧的无版本职业购买入口不再接受交易。已持久化结果与恢复凭据不会重新定价、重新抽取或重复扣费。

## 验证与文件

正式 `Check -Offline` 和97项JUnit通过，其中12项针对计分缺省、边界、逐块取整、批量逆运算、白名单与保存保护。隔离客户端 `LiveConfigScenario` 使用真实Minecraft、集成服务器、新建空岛世界和JEI 30.29.0.201，覆盖实际键盘、表单、全目录、购入价、真实BlockItem与建造杖放置、历史刷新、规则版本与权限边界；两种尺寸为1920×1080和1280×720，GUI比例2。

场景还验证动态蓝图覆盖重载后保留原等级、稀有度、基础估值及组件，固定弹药与仅收购商品拒绝改价；实际停止并重开测试世界的集成服务器，重新读取手改基础分后核对原始存量、分数、等级及首次里程碑奖励，重复重算不重复奖励。客户端进程保持运行，未另测独立服务器进程重启。

通告实测包括默认256块金块阈值的原版放置、重复跨越和建造杖，以及临时配置2／4／6块阈值后铁块三档逐一跨越、拆除后再跨越，共9条预期通告；默认256／2048／8192的运算边界另由单元测试覆盖。客户端Tooltip同时核对铁块末档保底1分和未配置大炮默认1分。

本地测试源码与脚本保留在被Git忽略的 `local-tests/`。验证结果见[验证摘要](LIVE_CONFIG_VALIDATION.json)，日志副本为 `build/live-config-final-client.log`；已目视检查[宽窗口配置](screenshots/live-config/config-wide.png)、[小窗口配置](screenshots/live-config/config-small.png)、[计分滚动](screenshots/live-config/config-scoring-scrolled.png)、[完整目录](screenshots/live-config/shop-all-small.png)、[小窗口改价](screenshots/live-config/shop-price-small.png)和[宽窗口改价](screenshots/live-config/shop-price-wide.png)。本轮未执行50人负载、整世界任意崩溃点或磁盘写满故障注入，不导出JAR或配置ZIP，不写入其它游戏实例。

默认同步工具为 `python tools/apply_live_editor_defaults.py`，只用于测试期显式同步仓库与项目开发TOML，已核验重复执行幂等；不是服务器启动时的升级或迁移流程。

## 后续JAR导出

用户随后要求导出JAR，已执行正式 `Export -Offline`，产物为 `build/libs/YumisSkyIsland-0.1.0-dev.jar`。包内23份默认TOML逐份与当前源码一致，正式编译类逐份一致，测试内容不打包。导出详情见验证摘要中的 `export`；未向其它游戏实例安装。

默认配置已经内置，无需另外安装配置ZIP。退出游戏／停服后，将实例 `config/yumis_sky_island` 旧配置目录备份移走，再启动会自动生成新版默认TOML；原有手改配置、收藏和布局偏好会随之重置。外置建筑库 `prefabs/yumis_sky_island` 独立保留，不由JAR生成。
