# 预制建筑与蓝图大炮

目标版本为 Minecraft 26.2 / Fabric。建筑数据放在服务器实例的 `prefabs/yumis_sky_island`，与模组 JAR 分开。建筑来源、原文件和转换记录见该目录的 `sources.json`、`originals/`；候选与上架状态见带中文注释的 `catalog.toml`。

本轮收录40份候选，**15份已通过验收并可购买**：7种生电（单羊羊毛、玄武岩、蜂蜜／蜜脾采收、16炉自动装载熔炉组、双高花、刷石、分类仓储），2座房屋、3座基地、3座奇观。另25份候选未上架，其中海带、TNT树场及苔藓机仍有装配／更新问题；不能把候选当作已兼容26.2的成品。机器目前只开放0°验收方向，房屋／基地／奇观使用原版四向旋转。

模组和23份默认配置由 `tools/dev.ps1 -Task Export` 导出；外置库由 `python tools/package_prefabs.py --package` 导出到 `build/libs/YumisSkyIsland-server-prefabs.zip`。把建筑包解压到运行实例根目录，得到 `prefabs/yumis_sky_island`；正常重启后才会上架图纸。开发实例 `run` 已有这份建筑库。

模组JAR同时用于服务器和客户端；外置建筑库只需服务器安装。配套配置ZIP是本轮23份默认TOML：测试实例可直接使用；保留管理员手改配置时，需要合并蓝图大炮、特殊弹药及对应等级／稀有度条目，不依赖自动迁移旧商品表。

## 玩家使用

1. 在现有商店购买蓝图大炮、建筑图纸和特殊弹药。高阶图纸沿每日／隐藏供货与队伍库存规则。
2. 手持图纸右键方块，显示半透明投影。调整东、西、南、北和高度，步长可切换1／5格，旋转90°，选择是否替换。Esc可走动观察，G回到定位界面，也能逐层查看。
3. 保存位置到图纸，再将图纸放入本队大炮的图纸槽。大炮与建筑必须在同一空岛维度、整座建筑位于本队领地。定位不要求玩家站在大炮旁。
4. 放入特殊弹药。选择自备材料或购买成品，确认费用和不可撤销提示后开工。自备材料可放在炮内、六面直接相邻的本队容器及其中一层潜影盒。
5. 大炮按阶段从下到上施工，依赖部件、红石、流体和装配实体后装。缺料、缺弹药或区块卸载时等待；补充或靠近加载后续建。生物、骨粉、燃料、剪刀、瓶子和药材由玩家补充，按机器说明启动。

特殊弹药每份实际售价1000摩拉／金币，提供1000次施工额度。一个实际新增或替换的非空气方块消耗一次；相同方块跳过，明确留空位置的清理不耗弹药。弹药槽内尚未拆包的额度与炮内剩余额度一起显示。替换的普通方块不掉落，不退还材料；既有容器、方块实体及大炮不能覆盖。

暂停后可继续；终止或拆炮后已建部分保留，图纸和成品费不退。剩余材料保留，拆炮时未用弹药额度随掉落弹药保留。没有撤销功能。

## 费用与配置

图纸基价、大炮基价仍适用现有行情及实际商店倍率。成品费固定，特殊弹药实际售价固定，不受常驻2.5倍率影响。

| 档位 | 图纸基价 | 成品费 | 默认等级／稀有度 |
|---|---:|---:|---|
| 房屋 | 1,000,000 | 20,000,000 | 5／普通 |
| 基础机器 | 250,000 | 5,000,000 | 10／普通 |
| 标准机器 | 1,250,000 | 25,000,000 | 25／稀有 |
| 生存基地 | 10,000,000 | 200,000,000 | 35／史诗 |
| 高级机器 | 5,000,000 | 125,000,000 | 50／史诗 |
| 大型机器 | 12,500,000 | 250,000,000 | 75／传说 |
| 奇观 | 100,000,000 | 2,000,000,000 | 60／传说 |

2026-10-16按确认方案将生电类别全部32份候选的图纸价、成品费降为原来的25%；逐模板人工定价仍以实际 `catalog.toml` 为准，房屋／基地／奇观不随此调整。大炮基价100,000，1级、普通常驻、仅购买。每次开工仍需购买一张建筑图纸；成品模式仍消耗特殊弹药。

`config/yumis_sky_island/gameplay/prefabs.toml` 控制间隔、弹药、模板容量、检查预算和建筑库位置。默认每5tick最多1块，可设1～100；异步落盘或服务器负载会延长实际间隔，不会短于配置间隔。每1000块理论至少4分10秒，十万块至少约6小时57分。模板明确的非空清理位置也占施工时间。

`catalog.toml` 每个模板可配置名称、来源、许可、图纸价、成品费、等级、稀有度、旋转白名单、维度、生物群系、X/Z对齐要求及使用说明。改价后重启；模板内容变化需重新验收并更新SHA256。`requireVerifiedTemplates=true` 时只有状态为`verified`且哈希匹配的文件上架，未验收的候选保留但不能购买。

## 导入与维护

```powershell
python tools/fetch_prefabs.py
python tools/fetch_prefabs.py --only wool_single
python tools/prefab_io.py input.litematic output.yprefab
```

支持 Litematica、现代 Sponge `.schem` 和原版结构NBT；ZIP内必须明确只有一份结构。不把下载验证网页当作结构，也不绕过网站挑战。旧数字ID `.schematic` 需先转换成现代格式。工具保留原文件、SHA256、元数据作者、来源和转换说明。

转换明确处理原版旧名、旧墙状态、多区域负尺寸与矿车坐标。补齐机器选区省略的最低层承托，计入石头用料；外观模板的砂砾等重力装饰换成相近的非重力建材，避免浮空路径掉落。草地仍会按原版光照变化，原作个别无承托的小装饰会按原版规则移除。原作者箱内赠品、生物、实体携带装备和运营耗材被移除；机器必要的过滤物和合成器禁用槽保留，并计入自备材料清单。模板支持逐格施工阶段覆盖；特殊TNT／矿车／方向敏感机器不能只靠通用排序判定可用。

自然女巫小屋、海底神殿和下界要塞的结构刷怪条件不会随模板生成。本服传送门按队伍中心路由，依赖普通跨维度传送门循环的方案不能直接套用。三维度都不为施工强制加载区块。

## 存档与验证边界

开工费用、图纸消费和任务头纳入队伍持久化流程；每步先强制写施工日志，再扣材料和放方块。目标、炮与供料容器按区块记录恢复凭据，保存期间阻止点击、漏斗、容器自身tick及目标修改。日志断尾只丢弃未完整写入的记录；施工绑定模板哈希和岛屿世代，重启按记录恢复，无离线补建。

57项JUnit覆盖26.2注册表、材料计数、旋转、图纸身份、弹药实际价格与日志断尾。客户端专项已验证定位保存、5tick最低间隔、相邻箱中一层潜影盒扣料、成品费只扣一次、缺弹药等待和重启续建。建筑的逐项原版摆放与产出结果记录在外置库的 `native-validation.json`；结构检查和实际产出检查分别记录，候选数量不代表全部通过生产验收。未做50人压力或任意掉电点的整世界联合故障保证。

[本轮验证摘要](PREFAB_VALIDATION.json)。已上架的7种机器均经过实际大炮搭建后产出验证，刷石机移除产物后重新生成10块石头；过滤仓储成功分流16个活塞。权限、冲突不扣费、暂停、终止不退款、原生铁镐拆炮及未用弹药返还也已通过实机断言。
